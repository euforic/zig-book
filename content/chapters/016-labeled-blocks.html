Most of Zig's control flow can be wrapped in a label. A label turns a block, a loop, or a switch into something you can break out of from arbitrarily deep inside — with a value, if you like.

Labeled blocks

A block prefixed with label: is an expression. break :label value yields value as the block's result. This is the canonical way to do "compute a value with intermediate variables" without a helper function:

${z(`const total: u32 = sum: { var acc: u32 = 0; for (items) |x| { if (x < 0) break :sum 0; // bail out with 0 acc += @intCast(x); } break :sum acc; };`)}

If you fall off the end of a labeled block without a break, the type is void and any value-using context is an error. Always end with a break or use it for its side effects only.

Labeled loops

You can label any loop and break or continue the outer one:

${z(`fn findInGrid(grid: []const []const u8, ch: u8) ?struct { row: usize, col: usize } { return outer: for (grid, 0..) |row, r| { for (row, 0..) |c, col| { if (c == ch) break :outer .{ .row = r, .col = col }; } } else null; }`)}

The else on a labeled for runs if no break fired, exactly like an unlabeled one. The labeled break :outer can carry a value of the loop's element type, and the surrounding expression evaluates to that.

Labeled switch

We previewed this in the chapter on switch. The "continue with a new value" form turns a switch into a small state machine:

${z(`const Token = enum { plus, minus, num, end }; fn parse(stream: *Lexer) i32 { var acc: i32 = 0; var sign: i32 = 1; sm: switch (stream.next()) { .plus => { sign = 1; continue :sm stream.next(); }, .minus => { sign = -1; continue :sm stream.next(); }, .num => |n| { acc += sign * n; sign = 1; continue :sm stream.next(); }, .end => return acc, } }`)}

The dispatch is reused; continue :sm expr restarts the switch with a new discriminator. We come back to this pattern in Chapter 37 with a complete state-machine example.

Why labels?

Labels are how Zig replaces several features it doesn't have:

  • No do-while: write a while (true) with a labeled break.
  • No "return from arbitrary block": labels do that.
  • No exceptions: labeled control flow plus error unions cover the same use cases.
  • No goto: labels are forward-only and structured.

The result is verbose by 21st-century standards and remarkably easy to read after a week.

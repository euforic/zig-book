Zig is distributed as a single self-contained tarball. The compiler, standard library, vendored libcs for cross-compilation, and the language reference all live in one folder. Installation is unpacking that folder somewhere on your PATH.

The official download

Go to ziglang.org/download and grab the 0.16.0 archive for your operating system and architecture.

${note("Signed releases", `

Every Zig archive is signed with minisign. Verifying signatures is optional but recommended, especially in pipelines. The public key lives on the download page.

`)}

Linux and macOS

${sh(`# Pick a place to keep tools mkdir -p ~/opt cd ~/opt # Download (replace ARCH-OS with your target, e.g. x86_64-linux) curl -LO https://ziglang.org/download/0.16.0/zig-ARCH-OS-0.16.0.tar.xz # Unpack tar -xf zig-ARCH-OS-0.16.0.tar.xz mv zig-ARCH-OS-0.16.0 zig-0.16.0 # Add to PATH (bash/zsh; adjust for your shell) echo 'export PATH="$HOME/opt/zig-0.16.0:$PATH"' >> ~/.profile source ~/.profile`)}

Windows

Download the .zip archive for x86_64-windows, unzip it somewhere stable like C:\\zig, and add that folder to your PATH via the System Properties → Environment Variables dialog. PowerShell will pick it up after a new shell.

Package managers

Most package managers ship Zig, but versions lag. Use them for convenience, not for following along with this book:

${sh(`# Homebrew (macOS / Linux) brew install zig # Snap (Linux) snap install zig --classic --beta # Arch Linux pacman -S zig # Windows (scoop) scoop install zig`)}

Version managers

A version manager is a clean way to pin a specific Zig release per project:

${sh(`# Stable release for this book zvm install 0.16.0 zvm use 0.16.0`)}

Verifying the install

${sh(`$ zig version 0.16.0 $ zig env`)}

zig env prints the compiler's view of the world: where its standard library lives, the default cache directory, the host target triple, and so on. If it runs without error, you're set.

What ships in the box

That single zig binary is more than a compiler. It is, at minimum:

  • A Zig compiler with its own LLVM-free backends for x86_64, aarch64, and WebAssembly in debug mode (LLVM is used for optimized builds and other targets).
  • A C compiler (zig cc) and C++ compiler (zig c++) that wrap Clang with built-in libcs for dozens of OS/arch combinations.
  • A build system runner (zig build) that executes build.zig scripts.
  • A C-to-Zig translator via zig translate-c and the build-system TranslateC step.
  • An object file inspector (zig objcopy), a unit-test runner, and a fuzzer.

Editor support

You don't need an IDE, but you'll be happier with one of these:

  • ZLS — the Zig Language Server. Works with VS Code, Neovim, Helix, Emacs, Sublime, and anything else that speaks LSP. Install via github.com/zigtools/zls; make sure the ZLS version matches your Zig version.
  • VS Code — install the official "Zig Language" extension, then point it at your zig binary and at zls.
  • Neovim — nvim-lspconfig ships a zls recipe; tree-sitter-zig handles highlighting.

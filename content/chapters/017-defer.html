defer and errdefer are how Zig replaces destructors. They're simple, predictable, and impossible to forget. After this chapter you'll wonder how other languages do without them.

defer

A defer statement schedules an expression to run when the enclosing scope exits — by return, by break, by error propagation, by any means.

${z(`pub fn main(init: std.process.Init) !void { const io = init.io; const file = try std.Io.Dir.cwd().openFile(io, "data.txt", .{}); defer file.close(io); var buf: [4096]u8 = undefined; var reader = file.reader(io, &.{}); const n = try reader.interface.readSliceShort(&buf); std.debug.print("read {} bytes\\n", .{n}); } // file.close() runs here, no matter how we get out`)}

Multiple defers in the same scope run in LIFO order — the last one queued runs first. This makes paired setup/teardown trivial:

${z(`pub fn main() !void { var allocator = std.heap.GeneralPurposeAllocator(.{}).init; defer _ = allocator.deinit(); const buf = try allocator.allocator().alloc(u8, 1024); defer allocator.allocator().free(buf); // do work; buf is freed first, then the GPA deinits. }`)}

What defer can do

A defer body can contain almost any expression: function calls, blocks, even if. It cannot return from the enclosing function (that would defeat the purpose), and it can't propagate errors with try — if you need to handle errors in cleanup, use a catch in the defer body.

${z(`defer file.close(io); // close is infallible in Zig 0.16`)}

errdefer

errdefer only runs if the scope exits via an error. On a normal return, the errdefer is skipped.

${z(`fn newConnection(addr: []const u8) !*Connection { const c = try allocator.create(Connection); errdefer allocator.destroy(c); // only frees on the error paths below try c.dial(addr); errdefer c.disconnect(); try c.handshake(); return c; // both errdefers cancelled; caller owns c }`)}

This is the pattern for constructors that allocate then do additional work that might fail. Each step adds another errdefer; on success they all evaporate.

${tip("Tracking partial state", "

Whenever you write a try on a step after you've acquired a resource, the very next line should usually be errdefer for cleanup. This habit prevents leaks on rare error paths without you having to enumerate them.

")}

errdefer can capture the error

You can write errdefer |err| to inspect which error caused the unwinding:

${z(`fn doStuff() !void { errdefer |err| { std.log.err("doStuff failed: {s}", .{@errorName(err)}); } try step1(); try step2(); }`)}

Order matters

A defer sees the state at the moment of execution, not the moment of declaration. If you defer a function call that captures a pointer, the pointer must still be valid when the defer fires:

${z(`fn bug(buf: []u8) void { defer process(buf); // captured by reference (slice is a fat pointer) if (buf.len < 8) return; // process(buf) runs at scope exit either way. }`)}

defer is not the same as RAII

RAII ties cleanup to a type. defer ties cleanup to a syntactic location. The difference matters:

  • You can defer arbitrary statements, not just calls to a destructor.
  • You can defer the cleanup of a resource whose type doesn't know it owns anything (a file descriptor, a mutex, a temporary).
  • Conversely, you have to remember to write the defer. Forgetting it is the most common bug in Zig.
${danger("Common mistake", "

defer free(x); right before reassigning x will free the new value, not the old one. Capture into a local if you need to defer a free for the value that's currently in scope.

")}

A complete example

${z(`pub fn loadConfig(io: std.Io, allocator: std.mem.Allocator, path: []const u8) ![]u8 { const file = try std.Io.Dir.cwd().openFile(io, path, .{}); defer file.close(io); const stat = try file.stat(io); const buf = try allocator.alloc(u8, stat.size); errdefer allocator.free(buf); var reader = file.reader(io, &.{}); const n = try reader.interface.readSliceShort(buf); if (n != stat.size) return error.ShortRead; return buf; }`)}

Trace the cleanup: the file is always closed; the buffer is freed only if we exit with an error. On success the caller owns the buffer and is responsible for freeing it.

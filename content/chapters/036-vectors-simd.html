Zig has first-class SIMD via the type @Vector(N, T): a fixed-length vector of N values of type T that uses SIMD registers and operations where the target supports them. Regular arithmetic operators (+, *, &, etc.) work element-wise. No intrinsics, no ifdef forests — write the math, get the vector code.

Making a vector

${z(`const std = @import("std"); const Vec4 = @Vector(4, f32); pub fn main() void { const a: Vec4 = .{ 1, 2, 3, 4 }; const b: Vec4 = .{ 10, 20, 30, 40 }; const sum = a + b; std.debug.print("{any}\\n", .{sum}); // { 11, 22, 33, 44 } }`)}

Element initialization uses an array literal. The compiler picks the right SIMD instructions for the target — SSE/AVX on x86, NEON on ARM, etc.

Element access

Index a vector to read or write a single element:

${z(`var v: @Vector(4, i32) = .{ 1, 2, 3, 4 }; v[0] = 99; const last = v[3]; // 4`)}

Vectors are not slices — there's no .len, no iteration with for. They are fixed-shape value types.

Reductions

@reduce collapses a vector to a scalar with a given operation:

${z(`const v: @Vector(4, i32) = .{ 1, 2, 3, 4 }; const total = @reduce(.Add, v); // 10 const product = @reduce(.Mul, v); // 24 const biggest = @reduce(.Max, v); // 4`)}

Available reductions: .Add, .Mul, .And, .Or, .Xor, .Min, .Max.

Predicates and selection

Comparing two vectors produces a vector of booleans:

${z(`const a: @Vector(4, i32) = .{ 1, 5, 3, 7 }; const b: @Vector(4, i32) = .{ 2, 4, 3, 8 }; const mask: @Vector(4, bool) = a > b; // { false, true, false, false } const c = @select(i32, mask, a, b); // pick from a where mask is true, b otherwise // c = { 2, 5, 3, 8 }`)}

@select is the standard "vector-aware if": no branches, all elements processed.

Shuffling

@shuffle rearranges elements from one or two vectors according to an index mask:

${z(`const a: @Vector(4, u8) = .{ 'a', 'b', 'c', 'd' }; const b: @Vector(4, u8) = .{ 'A', 'B', 'C', 'D' }; // Take a[0], b[1], a[2], b[3] -> { 'a', 'B', 'c', 'D' } const mixed = @shuffle(u8, a, b, @Vector(4, i32){ 0, ~@as(i32, 0), 2, ~@as(i32, 2) });`)}

Indices into a are non-negative; indices into b are bit-not'd. Awkward syntactically, very fast at runtime.

Splat: scalar to vector

Replicate a single value across all lanes:

${z(`const v: @Vector(8, f32) = @splat(3.14); // v == { 3.14, 3.14, ..., 3.14 }`)}

Common in expressions where you need to scale a vector by a constant.

Casting between vectors and arrays

A vector and an array of the same shape are layout-compatible (subject to alignment). Convert with regular casts or @bitCast:

${z(`const arr: [4]f32 = .{ 1, 2, 3, 4 }; const v: @Vector(4, f32) = arr; // implicit, in some contexts const back: [4]f32 = v; // also works`)}

This makes it natural to load a slice into a vector, do work, and store the result back.

Picking N

The right N depends on the target. The standard library exposes std.simd.suggestVectorLength(T) to get a reasonable default for the current target:

${z(`const std = @import("std"); const N = std.simd.suggestVectorLength(f32) orelse 4; const V = @Vector(N, f32); fn sum(xs: []const f32) f32 { var acc: V = @splat(0); var i: usize = 0; while (i + N <= xs.len) : (i += N) { acc += @as(V, xs[i..][0..N].*); } var total = @reduce(.Add, acc); while (i < xs.len) : (i += 1) total += xs[i]; return total; }`)}

This is the canonical SIMD loop: vectorize the bulk, tail-handle the remainder.

Caveats

  • Vector lengths must be comptime-known.
  • Alignment matters: loads from a misaligned pointer to a vector are slower (and can be UB on some targets). Use slices that you've aligned, or use @alignCast when you've checked manually.
  • The compiler may legalize unusual widths by splitting into smaller instructions. Profile if it matters.

The standard library is where Zig turns from a language into a toolchain. It contains the everyday building blocks you expect from a systems language: allocation, formatting, bytes, containers, I/O, filesystem access, processes, networking, crypto, JSON, tests, target metadata, and enough compiler/build integration to make cross-platform work practical.

The fastest way to learn it is to read it. The public surface starts in std.zig; the implementation lives beside it in small files like Io.zig, mem.zig, heap.zig, and directories like crypto/, http/, and json/.

For version-sensitive APIs, prefer the source over memory. Generated docs are useful for browsing, but the source shows deprecation notes, error sets, options structs, and implementation details in the same place.

The everyday modules

ModuleUse it forNotes
std.memSlices, byte operations, searching, trimming, tokenizing, copying, alignment.Reach for this any time you are manipulating []T or []u8.
std.fmtFormatting, parsing integers/floats, compile-checked format strings.Formatting powers std.debug.print, writers, logs, and error messages.
std.heapAllocators: debug, arena, fixed-buffer, page, SMP, C allocator.Zig allocation is explicit; if a function allocates, an allocator should be visible.
std.ArrayList, std.AutoHashMap, std.StringHashMapGrowable arrays and hash maps.In 0.16, ArrayList(T) is allocator-at-call-site; hash maps still store allocators unless you use unmanaged forms.
std.array_hash_mapOrder-preserving maps.Use when iteration order matters.
std.sortSorting slices.Sort algorithms take context and comparison functions instead of hidden callbacks.
std.testingAssertions, temporary allocators, test helpers.Use std.testing.allocator for leak-checked unit tests.

System and runtime modules

ModuleUse it forNotes
std.IoReaders, writers, files, directories, networking, sleeping, randomness, task groups, synchronization.This is the central 0.16 runtime interface. Most OS-facing examples should accept io: std.Io.
std.Io.Dir and std.Io.FileFilesystem and file-handle work.Directory handles keep path roots explicit.
std.processArguments, environment, child processes, current/executable paths, exit.Use std.process.Init for real programs in 0.16.
std.Thread and std.atomicRaw threads and atomic operations.Waiting primitives that may suspend moved toward std.Io; use raw threads for CPU parallelism.
std.posix, std.os, std.cLow-level platform and libc integration.Use only when the higher-level cross-platform abstraction is not enough.
std.log and std.debugLogging, assertions, stack traces, panic/debug output.std.debug.print writes to stderr and is for diagnostics, not normal app output.

How to choose

  • Start with the highest-level module that says what you mean: std.json for JSON, std.Io.Dir for files, std.crypto for security, std.Build for build scripts.
  • Drop to std.posix, std.os, or object-format modules only when you need platform-specific behavior.
  • When a module allocates, look for allocator ownership in the type or method signatures.
  • When an operation can block, sleep, wait, touch the OS, or request entropy, expect a std.Io shape in 0.16.
  • Before copying outside examples, verify them against your installed std_dir.

An ordinary Zig struct lays out its fields with padding for alignment, in declaration order — but the compiler is free to add bytes between fields if that makes access faster. For most code that's fine. For hardware registers, network packets, and on-disk file formats, you need exact control. That's packed struct.

The three layouts

Zig structs come in three layouts:

  • struct — natural layout. Compiler may pad and reorder for performance. Default.
  • extern struct — C-ABI layout. Fields in declaration order, padding per C rules. Use for FFI.
  • packed struct — bit-level layout. Fields packed at exactly the bit width you specified. Backed by an integer.
${z(`const Color = packed struct { r: u5, g: u6, b: u5, }; // exactly 16 bits comptime { std.debug.assert(@bitSizeOf(Color) == 16); std.debug.assert(@sizeOf(Color) == 2); }`)}

A packed struct is essentially an integer with named bit fields. You read/write it like a struct; the compiler does the masking and shifting.

Casting to and from the backing integer

You can convert between a packed struct and its underlying integer with @bitCast:

${z(`const c: Color = .{ .r = 0x1F, .g = 0x00, .b = 0x1F }; const word: u16 = @bitCast(c); const back: Color = @bitCast(word); std.debug.assert(back.r == 0x1F);`)}

This is how you build a packet header in memory, send it as bytes, and reconstruct it on the other end with zero serialization code.

Packed unions

A packed union overlays fields at the same bits. Each field must be the same bit width:

${z(`const Reg = packed union { raw: u32, fields: packed struct { flags: u8, count: u16, version: u8, }, }; var r: Reg = .{ .raw = 0xDEAD_BEEF }; std.debug.print("flags = {x}\\n", .{r.fields.flags});`)} ${note("Packed-union rules", "

Packed unions can declare an explicit backing integer with packed union(u32) { ... }, and equality comparison (==) works between packed unions of the same type. Pointer-typed fields are not allowed in packed structs or unions, and packed unions may not have unused bits.

")}

Bit-level slices and arrays

Inside a packed struct, you can use small-width integers and even bool fields (each takes one bit):

${z(`const Flags = packed struct { enabled: bool, visible: bool, locked: bool, _reserved: u5 = 0, }; const f: Flags = .{ .enabled = true, .visible = true, .locked = false }; const byte: u8 = @bitCast(f);`)}

This is how you map MMIO registers, ELF headers, instruction encodings — anything where the spec gives you bit positions.

Endianness

Packed structs use the host endianness by default. When you need a specific order, use the integer-side helpers:

${z(`const Header = packed struct { magic: u32, version: u16, flags: u16, }; const h: Header = .{ .magic = 0xCAFEBABE, .version = 1, .flags = 0 }; const word: u64 = @bitCast(h); const be = std.mem.nativeToBig(u64, word); try writer.writeAll(std.mem.asBytes(&be));`)}

For richer endianness control across a whole struct, std.mem.writeInt / readInt / byteSwapAllFields exist.

extern struct: when you must talk C

For C-compatible layouts, extern struct is the right tool. It uses the platform's C ABI: fields in source order, padding to align each field naturally.

${z(`const Stat = extern struct { dev: u64, ino: u64, mode: u32, nlink: u32, // ... }; extern fn fstat(fd: i32, statbuf: *Stat) i32;`)}

For an MMIO register set or a hardware command block, extern struct plus volatile pointer reads gives you what assembly would.

When to reach for each

  • Internal data structure → plain struct.
  • Crosses a C boundary → extern struct.
  • Bit-exact layout (registers, wire formats) → packed struct.

The choice is structural — change layout, change keyword, all the access syntax stays the same.

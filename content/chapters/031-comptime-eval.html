Most languages have two languages: the runtime language and a macro language. Zig has one. The same code that runs your program also runs your build-time metaprogramming. Functions, control flow, structs, even string parsing — all of it can execute at compile time, producing values, types, or whole structs as output.

The mechanism is the keyword comptime. It marks values, parameters, blocks, and expressions as "evaluate this before the program runs."

comptime values

A comptime variable is computed at compile time. Its value is known to the compiler:

${z(`comptime var counter: u32 = 0; comptime { counter += 1; counter *= 2; } // counter is now 2 — at compile time const std = @import("std"); pub fn main() void { std.debug.print("counter = {}\\n", .{counter}); }`)}

The variable doesn't exist at runtime — it's been folded into the program's constants.

comptime blocks

A bare comptime { ... } block runs at compile time. Useful for assertions about types, sizes, or alignments:

${z(`comptime { if (@sizeOf(usize) != 8) @compileError("64-bit only, sorry"); std.debug.assert(@bitSizeOf(u8) == 8); }`)}

@compileError aborts compilation with a message. @compileLog prints a debug message during compilation. These exist because compile-time code can't write to stdout.

comptime parameters

A function parameter marked comptime must be known at compile time, and the function is specialized for each value:

${z(`fn repeat(comptime count: usize, value: u8) [count]u8 { var buf: [count]u8 = undefined; @memset(&buf, value); return buf; } const eights = repeat(8, '8'); // type is [8]u8 const fives = repeat(5, '5'); // type is [5]u8 — different function instance`)}

Notice the type of the result depends on a parameter. That's only possible because count is comptime; runtime values can't influence types.

Types are first-class

The big idea: type is itself a type. Functions can take and return types. Variables can hold types. All of this happens at comptime.

${z(`fn Pair(comptime A: type, comptime B: type) type { return struct { first: A, second: B, }; } const IntStr = Pair(i32, []const u8); const p: IntStr = .{ .first = 42, .second = "hi" };`)}

Pair is a function that, given two types, returns a new struct type. We just spelled generics — with no special syntax.

comptime is contagious

An if, while, or switch whose condition is known at comptime can do things impossible at runtime: branch on types, declare variables of different types per branch, generate different code paths per build:

${z(`fn isSigned(comptime T: type) bool { return switch (@typeInfo(T)) { .int => |info| info.signedness == .signed, else => false, }; } comptime { std.debug.assert(isSigned(i32)); std.debug.assert(!isSigned(u32)); }`)}

Inline for and unrolled loops

inline for is a comptime loop that unrolls at compile time. The loop variable is comptime-known on each iteration:

${z(`fn printFields(value: anytype) void { const T = @TypeOf(value); inline for (@typeInfo(T).@"struct".fields) |field| { std.debug.print("{s} = {any}\\n", .{ field.name, @field(value, field.name) }); } }`)}

The body runs once at compile time per field; the generated code has each print baked in with the field name as a literal.

When is something comptime?

Zig is aggressive about evaluating things at compile time. The general rule: if all the inputs to an expression are comptime-known, the result is comptime-known. Things that require comptime:

  • Types (you can't have a runtime type value).
  • Array length expressions, like the N in [N]T.
  • The condition of an inline if, inline for, inline while.
  • comptime-marked parameters.
  • The arguments to many builtins (@field, @hasDecl, @typeInfo).

The forbidden things

Comptime code runs in a deterministic sandbox: it can't open files, do I/O, take the address of a runtime value, or call functions through opaque pointers. @embedFile is the way to pull files into the program; @import is the way to bring in other modules. There is no general comptime FFI.

The sandbox is what makes comptime safe to rely on. The same source, compiled twice, produces the same binary.

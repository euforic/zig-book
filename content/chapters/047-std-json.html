JSON support in Zig is full-featured: parse to dynamic Value, parse into a typed struct, serialize a struct, stream-parse a giant document without allocating, stream-serialize, custom field handling, the works. std.json punches above its weight.

Parse to a typed struct

${z(`const Config = struct { name: []const u8, port: u16, debug: bool = false, tags: []const []const u8 = &.{}, }; const src = \\\\{ "name": "api", "port": 8080, "tags": ["alpha", "beta"] } ; const parsed = try std.json.parseFromSlice(Config, allocator, src, .{}); defer parsed.deinit(); std.debug.print("{s}:{}\\n", .{ parsed.value.name, parsed.value.port });`)}

parseFromSlice returns a Parsed(T) that owns all the allocated memory (strings, sub-arrays). When you deinit(), everything frees together.

Field defaults and missing fields

If a JSON object lacks a field that has a Zig default, the default is used. If a field has no default and is missing, you get error.MissingField. To allow unknown JSON keys, pass .ignore_unknown_fields = true:

${z(`const parsed = try std.json.parseFromSlice(Config, allocator, src, .{ .ignore_unknown_fields = true, });`)}

Optional, union, enum

Zig types map naturally:

  • ?T ↔ null or a value.
  • Tagged union ↔ object with a single key matching the tag (default; configurable).
  • Enum ↔ string of the tag name.
  • Numeric types ↔ JSON number, with range checks.

Custom field handling

For full control over how a type parses (renaming fields, custom validation), implement pub fn jsonParse(allocator, source, options) !T on the type. The same method on the writer side is jsonStringify.

Dynamic Value

When you don't know the shape ahead of time:

${z(`const parsed = try std.json.parseFromSlice(std.json.Value, allocator, src, .{}); defer parsed.deinit(); const root = parsed.value; switch (root) { .object => |obj| { if (obj.get("name")) |name| { std.debug.print("name = {s}\\n", .{name.string}); } }, else => return error.NotObject, }`)}

Value is a tagged union: null, bool, integer, float, number_string, string, array, object. Navigate it with switches.

Serializing

${z(`var out: std.ArrayList(u8) = .empty; defer out.deinit(allocator); try std.json.stringify(.{ .name = "service", .port = @as(u16, 8080), .tags = &[_][]const u8{ "alpha", "beta" }, }, .{ .whitespace = .indent_2 }, out.writer(allocator)); std.debug.print("{s}\\n", .{out.items});`)}

The whitespace option controls indentation: .minified, .indent_2, .indent_4, .indent_tab.

Streaming parser

For large documents you don't want to load into memory:

${z(`var stream = std.json.Scanner.initStreaming(allocator); defer stream.deinit(); while (true) { var buf: [4096]u8 = undefined; const n = try src_reader.read(&buf); if (n == 0) { stream.endInput(); } else { stream.feedInput(buf[0..n]); } while (true) { const tok = stream.next() catch |e| switch (e) { error.BufferUnderrun => break, else => return e, }; if (tok == .end_of_document) return; // handle tok ... } }`)}

You drive the scanner with bytes; it yields tokens (object_begin, key, string, number, etc.). This is how you process gigabyte JSON without ever holding it all at once.

Streaming writer

Likewise, a WriteStream emits a JSON document incrementally:

${z(`var w = std.json.writeStream(output_writer, .{ .whitespace = .indent_2 }); defer w.deinit(); try w.beginObject(); try w.objectField("status"); try w.write("ok"); try w.objectField("items"); try w.beginArray(); for (items) |item| try w.write(item); try w.endArray(); try w.endObject();`)}

This pattern is the right shape for streaming HTTP responses where you can't (or don't want to) build the entire JSON in memory before sending.

Error handling

Parse errors include the byte offset and a kind tag (UnexpectedEndOfInput, SyntaxError, UnexpectedToken, etc.). When parsing into a typed struct, additional errors include MissingField, UnknownField, and type-mismatch errors. Most code can just try and propagate.

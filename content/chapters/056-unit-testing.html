Zig has unit testing baked into the language. There's no framework, no external runner, no separate test directory convention. You write test blocks next to the code they exercise, and zig build test runs them.

The test block

${z(`const std = @import("std"); fn double(x: i32) i32 { return x * 2; } test "double returns twice the input" { try std.testing.expectEqual(@as(i32, 4), double(2)); try std.testing.expectEqual(@as(i32, -10), double(-5)); } test "double of zero is zero" { try std.testing.expectEqual(@as(i32, 0), double(0)); }`)}

Tests are top-level declarations. They have an optional string label, a body that returns !void (it can fail). Inside, you call assertion helpers from std.testing. Any error returned from a test is a test failure.

The std.testing assertions

  • expect(condition: bool) — fail if false. Use for ad-hoc checks.
  • expectEqual(expected, actual) — fail if not equal. Works for primitives, structs, enums, tagged unions.
  • expectEqualStrings(expected, actual) — byte-equality on slices, with a useful diff message on failure.
  • expectEqualSlices(T, expected, actual) — slice comparison for any element type.
  • expectEqualDeep(expected, actual) — recursive structural equality, follows pointers and slices.
  • expectError(expected_err, result) — fail unless the expression returned exactly this error.
  • expectApproxEqAbs / expectApproxEqRel — for floats with tolerance.
${tip('When expectEqual fails, the error message includes the expected and actual values. expectEqualStrings goes further and shows the differing byte offset. Choose the most specific helper available — better failure messages save debugging time.')}

Testing functions that allocate

${z(`fn dup(allocator: std.mem.Allocator, s: []const u8) ![]u8 { const out = try allocator.alloc(u8, s.len); @memcpy(out, s); return out; } test "dup copies bytes" { const allocator = std.testing.allocator; const copy = try dup(allocator, "hello"); defer allocator.free(copy); try std.testing.expectEqualStrings("hello", copy); }`)}

std.testing.allocator is a special allocator that tracks every allocation. If your test exits with leaked memory, the runner reports the leak and fails the test. This is invaluable: leak-free APIs are validated automatically.

Expected errors

${z(`fn parsePositive(s: []const u8) !u32 { const n = try std.fmt.parseInt(i64, s, 10); if (n < 0) return error.Negative; return @intCast(n); } test "rejects negative numbers" { try std.testing.expectError(error.Negative, parsePositive("-3")); } test "rejects garbage" { try std.testing.expectError(error.InvalidCharacter, parsePositive("nope")); }`)}

Running tests

${sh(`# Run all tests reachable from src/main.zig zig test src/main.zig # Run tests through the build system (uses your build.zig settings) zig build test # Run tests matching a filter zig build test -Dtest-filter="parser" # Pass an allocator failure rate to stress-test error paths zig build test -Dtest-failing-allocator-rate=10`)}

The compiler discovers tests by traversing imports from the test root. If module A imports B, and B imports C, then tests in all three run. This is why the conventional setup is to put a single comprehensive test root in src/root.zig that imports the modules you want exercised.

Wiring tests in build.zig

${z(`const tests = b.addTest(.{ .root_module = b.createModule(.{ .root_source_file = b.path("src/root.zig"), .target = target, .optimize = optimize, }), }); const run_tests = b.addRunArtifact(tests); run_tests.timeout_ms = 60_000; // 0.16 per-test timeout const test_step = b.step("test", "Run unit tests"); test_step.dependOn(&run_tests.step);`)}

Property-based testing via comptime

Zig doesn't ship a property-based testing library, but the language makes one easy to roll yourself. Use std.Random seeded deterministically, generate inputs in a loop, assert invariants.

${z(`test "addition is commutative" { var prng = std.Random.DefaultPrng.init(12345); const r = prng.random(); var i: usize = 0; while (i < 1000) : (i += 1) { const a = r.int(i64); const b = r.int(i64); try std.testing.expectEqual(a +% b, b +% a); } }`)} ${warn('Always seed deterministically in tests. If a property test fails, you need to be able to reproduce the failure exactly. A random seed plus a logging line on failure (\"failed with seed=N\") is the minimal CI-friendly pattern.')}

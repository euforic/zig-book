Numerics in Zig are stricter than in C and richer than in most modern languages. There are no implicit conversions between numeric types — even u8 and u16 require an explicit widening — and you can declare integers of arbitrary bit widths.

Signed and unsigned integers

The standard sizes:

SignedUnsignedWidth
i8u88 bits
i16u1616 bits
i32u3232 bits
i64u6464 bits
i128u128128 bits
isizeusizepointer-width

Arbitrary-width integers

Any iN or uN for N from 0 to 65535 is a real type:

${z(`const flags: u3 = 0b101; const six_bit_color: u6 = 42; const huge: i1024 = (1 << 1000); // 1024-bit signed integer const nothing: u0 = 0; // takes zero bytes`)}

The compiler handles odd widths properly: a u3 is stored in 8 bits in memory but the upper 5 are inaccessible without an explicit cast. Inside a packed struct, the sizes pack at the bit level. We'll see that in Chapter 33.

Integer literals

Literals come in several forms:

${z(`const dec: i32 = 42; const hex: i32 = 0x2A; const oct: i32 = 0o52; const bin: i32 = 0b00101010; const big: u64 = 1_000_000; // underscores for readability`)}

The comptime_int type

An untyped integer literal has type comptime_int — an arbitrary-precision integer that lives only at compile time. It coerces to any concrete integer type that can hold its value:

${z(`const a: u8 = 250; // 250 fits in u8 → ok const b: u8 = 300; // error: 300 out of range for u8 const huge = 1 << 100; // type is comptime_int; 0 runtime cost`)}

Conversions

Zig refuses implicit narrowing or signedness changes. Use builtins:

${z(`const x: i32 = 100; const y: i64 = x; // ok: safe widening const a: i32 = 100_000; const b: i16 = @intCast(a); // explicit narrow; runtime checked in Debug const c: u32 = @intCast(-1); // runtime panic: -1 doesn't fit in u32 const d: u32 = @bitCast(-1); // reinterpret bits: 0xFFFFFFFF const e: i32 = @truncate(0xFFFFFFFF_FFFFFFFF); // drop high bits`)}

Four operations, each with a different intent:

  • @intCast(x) — change integer type, value must fit; checked at runtime in safe builds.
  • @bitCast(x) — reinterpret the bits without changing the bit pattern. Source and dest must have the same size.
  • @truncate(x) — chop off high bits to fit a narrower type. Never traps.
  • @as(T, x) — explicit type assertion for ambiguous expressions; doesn't change values, but tells the compiler what type to pick.

Overflow

Zig is strict about overflow. The behavior depends on the operator:

OpWrappingSaturatingDefault
Add+%+|+ (panics on overflow in Debug)
Sub-%-|-
Mul*%*|*
Shl<<%<<|<<
${z(`const x: u8 = 250; const a = x + 10; // panics in Debug/Safe: overflow const b = x +% 10; // wraps: 4 const c = x +| 10; // saturates: 255 const carry = @addWithOverflow(x, 10); // returns: struct{ u8, u1 } — sum and overflow bit`)}

For checked arithmetic without panics, the @addWithOverflow, @subWithOverflow, @mulWithOverflow, and @shlWithOverflow builtins return a struct of { result, overflow_bit }.

Floats

Zig has f16, f32, f64, f80, and f128. The first three are the usual IEEE 754 sizes; f80 is x86 extended precision; f128 is IEEE quadruple precision (supported in software on most targets).

${z(`const a: f32 = 3.14; const b: f64 = 1.0e-10; const c: f128 = 1.0; const d: f16 = 0.5;`)}

Float literals

An untyped float literal has type comptime_float, analogous to comptime_int.

${z(`const x = 1.5; // comptime_float const y: f32 = x; // ok const a: f64 = 1.0 / 3.0; // computed at comptime, then assigned`)}

Float specials

${z(`const std = @import("std"); const inf = std.math.inf(f32); const nan = std.math.nan(f32); const eps = std.math.floatEps(f32); // Comparisons: const a: f32 = 0.1 + 0.2; const b: f32 = 0.3; const close = std.math.approxEqAbs(f32, a, b, 1e-6);`)}

Int ↔ Float conversion

${z(`const i: i32 = 42; const f: f64 = @floatFromInt(i); const back: i32 = @intFromFloat(f); // truncates toward zero // @floor, @ceil, @round, and @trunc return floats. // To get an integer, use @intFromFloat after the rounding builtin: const r: i32 = @intFromFloat(@round(3.7)); // → 4`)}

Bitwise and shift operators

${z(`const x: u8 = 0b1100; const y: u8 = 0b1010; const both = x & y; // 0b1000 const either = x | y; // 0b1110 const xor = x ^ y; // 0b0110 const inv = ~x; // 0b00110011 const sh = x << 2; // 0b110000 — overflow if it doesn't fit const shr = x >> 1; // 0b0110`)}

The shift count's type must be a small unsigned integer — usually u3 for a u8, u6 for u64, etc. The compiler picks the right width.

A word on usize

usize is the integer type the same width as a pointer on the target. It's what array indexing and len use. isize is its signed cousin. On 64-bit machines both are 64-bit; on 32-bit machines both are 32-bit. Whenever you index into memory or count bytes, reach for usize.

Filesystem operations live under std.Io.Dir and std.Io.File. The design is organized around directory handles rather than global path strings, and operations that touch the OS take an explicit io handle.

The cwd shortcut

${z(`const std = @import("std"); pub fn main(init: std.process.Init) !void { const io = init.io; const cwd = std.Io.Dir.cwd(); const file = try cwd.openFile(io, "data.txt", .{}); defer file.close(io); var file_buf: [4096]u8 = undefined; var out_buf: [256]u8 = undefined; var reader = file.reader(io, &file_buf); const n = try reader.interface.readSliceShort(&out_buf); std.debug.print("{s}", .{out_buf[0..n]}); }`)}

cwd() is a directory handle for "wherever the process happens to be." Closing the special cwd handle is illegal. Long-running services that change the working directory or care about race resistance usually open a stable directory handle explicitly.

Reading and writing files

${z(`// Read everything const data = try cwd.readFileAlloc(io, "input.txt", allocator, .limited(1 << 24)); defer allocator.free(data); // Write everything try cwd.writeFile(io, .{ .sub_path = "output.txt", .data = "hello\\n" }); // Stream const f = try cwd.createFile(io, "log.txt", .{}); defer f.close(io); var write_buf: [4096]u8 = undefined; var writer = f.writer(io, &write_buf); defer writer.interface.flush() catch {}; try writer.interface.print("line {}\\n", .{42});`)}

Directory operations

${z(`try cwd.createDir(io, "subdir", .default_dir); try cwd.createDirPath(io, "a/b/c"); // makes intermediate dirs var dir = try cwd.openDir(io, "subdir", .{ .iterate = true }); defer dir.close(io); var it = dir.iterate(); while (try it.next(io)) |entry| { std.debug.print("{s} ({s})\\n", .{ entry.name, @tagName(entry.kind) }); } try cwd.deleteFile(io, "temp.txt"); try cwd.deleteDir(io, "empty_dir"); try cwd.deleteTree(io, "path/to/wipe"); // recursive`)}

To iterate, open the directory with .iterate = true. The returned iterator yields {name, kind} entries.

Walking a tree

For recursive walks, use walk:

${z(`var dir = try cwd.openDir(io, ".", .{ .iterate = true }); defer dir.close(io); var walker = try dir.walk(allocator); defer walker.deinit(); while (try walker.next(io)) |entry| { if (entry.kind == .file) { std.debug.print("{s}\\n", .{entry.path}); } }`)}

walk is convenience over walkSelectively. Use the selective walker when you need to prune directories like zig-cache, .git, or node_modules without descending into them.

Path helpers

${z(`const p = try std.Io.Dir.path.join(allocator, &.{ "/etc", "nginx", "nginx.conf" }); defer allocator.free(p); const dirname = std.Io.Dir.path.dirname(p); // "/etc/nginx" const basename = std.Io.Dir.path.basename(p); // "nginx.conf" const ext = std.Io.Dir.path.extension(p); // ".conf" const stem = std.Io.Dir.path.stem(p); // "nginx" const abs = try std.Io.Dir.path.resolve(allocator, &.{"./rel", "../sib"}); defer allocator.free(abs);`)}

std.Io.Dir.path handles platform-specific separators. Use it before hand-building paths with string concatenation.

Atomic and temporary files

For "write a config file, replace the old one only if write succeeded," create an atomic file, write to its real file handle, flush, then replace:

${z(`var atomic = try cwd.createFileAtomic(io, "config.toml", .{ .make_path = true, .replace = true, }); defer atomic.deinit(io); var buffer: [4096]u8 = undefined; var writer = atomic.file.writer(io, &buffer); try writer.interface.writeAll(new_contents); try writer.interface.flush(); try atomic.replace(io);`)}

Metadata

${z(`const stat = try cwd.statFile(io, "data.txt", .{}); std.debug.print("size = {} bytes\\n", .{stat.size}); std.debug.print("mtime = {}\\n", .{stat.mtime}); const f = try cwd.openFile(io, "data.txt", .{}); defer f.close(io); const fst = try f.stat(io); _ = fst;`)}

realpath, max_path_bytes

${z(`var buf: [std.Io.Dir.max_path_bytes]u8 = undefined; const n = try cwd.realPathFile(io, "rel/link", &buf); const real = buf[0..n];`)}

max_path_bytes is the platform-appropriate maximum. Use it for stack path buffers; allocate when paths may be longer than the fixed buffer.

Working with file modes and permissions

${z(`const script = try cwd.createFile(io, "script.sh", .{ .permissions = .executable_file, }); defer script.close(io); try cwd.setFilePermissions(io, "script.sh", .executable_file, .{});`)}

On Windows, permissions map to file attributes; on POSIX they map to mode bits and are still affected by the process umask. Portable code should treat permissions as policy, not as a guaranteed exact final mode.

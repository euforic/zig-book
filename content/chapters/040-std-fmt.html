Zig has no printf. It has std.fmt: a small set of routines built around comptime-checked format strings. The format string is parsed at compile time, the argument types are inspected at compile time, and any mismatch is a build error. Runtime cost is what you'd expect from a printf — just without the footguns.

The basics

${z(`const std = @import("std"); pub fn main() void { std.debug.print("hello {s}, you are {} years old\\n", .{ "alice", 30 }); }`)}

The first argument is the format string. The second is a tuple (anonymous struct) of arguments. Each placeholder in the string consumes one tuple element.

Placeholder syntax

A placeholder is {spec}. The spec selects how the argument is rendered. The common ones:

  • {} — default for the type. Numbers in decimal, strings as bytes, etc.
  • {s} — render as string (for []const u8).
  • {d} — decimal integer.
  • {x} / {X} — lowercase/uppercase hex.
  • {b} — binary.
  • {o} — octal.
  • {c} — single byte as a char.
  • {e} / {E} — scientific notation float.
  • {any} — generic dump using @typeInfo, useful for debugging.
  • {*} — pointer address.

Width, alignment, fill

The full spec is {[width][.precision][specifier]} with optional alignment prefix:

${z(`std.debug.print("{d:5}\\n", .{42}); // " 42" width 5, right aligned std.debug.print("{d:<5}\\n", .{42}); // "42 " left aligned std.debug.print("{d:0>5}\\n", .{42}); // "00042" fill char 0 std.debug.print("{e:.3}\\n", .{3.14159}); // 3.142e0 std.debug.print("{s:.<10}\\n", .{"hi"}); // "hi........"`)}

The four shapes of formatter

Beyond std.debug.print (which writes to stderr), the formatting routines come in a small family:

${z(`// Allocate a formatted string const s = try std.fmt.allocPrint(allocator, "{} bytes", .{n}); defer allocator.free(s); // Format into a caller-provided buffer var buf: [64]u8 = undefined; const slice = try std.fmt.bufPrint(&buf, "x = {d}", .{x}); // Format to any writer (file, stream, etc.) try writer.print("{s}\\n", .{name}); // Just compute the rendered length (no output) const n = std.fmt.count("{} bytes", .{n});`)}

The same format strings work everywhere. Pick the routine by where the output goes.

Custom format methods

A type can define its own formatting by implementing fn format(self, writer) !void. When you place a value of that type in a placeholder, your method runs:

${z(`const Vec3 = struct { x: f32, y: f32, z: f32, pub fn format(self: Vec3, writer: anytype) !void { try writer.print("({d:.2}, {d:.2}, {d:.2})", .{ self.x, self.y, self.z }); } }; std.debug.print("v = {}\\n", .{Vec3{ .x = 1, .y = 2, .z = 3 }}); // v = (1.00, 2.00, 3.00)`)}

This is duck-typed: any type with a matching format method participates. The signature shape may vary slightly across stdlib versions; see the docs for the exact form.

Parsing

std.fmt isn't just for printing. It also parses:

${z(`const n = try std.fmt.parseInt(i32, "42", 10); // base 10 const f = try std.fmt.parseFloat(f64, "3.14"); const u = try std.fmt.parseUnsigned(u64, "0xff", 0); // auto-detect base from prefix`)}

Both return error unions on malformed input. There's no silent zero on failure.

Compile-time validation

If you write {d} with a string argument, or supply two args for one placeholder, the build fails:

${z(`// std.fmt.print("hello {d}", .{"world"}); // build error: invalid format string '{d}' for type '[]const u8'`)}

This catches an entire class of bugs that bedevil C and many dynamic languages. The cost is that format strings cannot be runtime-computed — but that's also a security win, since format-string injection is impossible.

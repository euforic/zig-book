Three types whose roles are easily confused: bool, void, and noreturn. None of them is interchangeable with the others.

bool

bool has exactly two values: true and false. It is a real one-byte type, but unlike C, it does not coerce to or from integers. You cannot write if (1).

${z(`var flag: bool = true; if (flag) { flag = false; } // Logical operators short-circuit: const x: ?i32 = null; if (x != null and x.? > 0) { // x.? not evaluated if x == null }`)}

and and or are short-circuiting and only work on booleans. ! negates. There's no && or ||.

Bool ↔ Int

${z(`const b: bool = true; const n: u1 = @intFromBool(b); // 1 const b2: bool = (n == 1); // explicit comparison`)}

The @intFromBool builtin returns a u1. To go back, compare.

void

void is the "no value" type. It has exactly one value, also written void (or more commonly {} when you need to spell it). It's used as a return type, as a field whose presence carries information but no data, and as the value type of sets.

${z(`fn greet() void { std.debug.print("hi\\n", .{}); } // A set is just a hash map with void values: var seen = std.AutoHashMap(u32, void).init(allocator); try seen.put(42, {}); // A "phantom" field that takes zero space: const Marker = struct { important: void = {}, value: i32, };`)}

A void field takes zero bytes. A function that returns void ends with an implicit return;.

${note("void is not C's void", "

In C, void means \"no type\" — a placeholder. In Zig it's a real type with one inhabitant. The Zig equivalent of C's void* is ?*anyopaque (an optional pointer to an opaque type).

")}

noreturn

noreturn is the type of expressions and functions that never produce a value because they don't return. return, break, continue, unreachable, and infinite loops all have type noreturn. std.process.exit has return type noreturn.

${z(`fn fatal(msg: []const u8) noreturn { std.debug.print("fatal: {s}\\n", .{msg}); std.process.exit(1); } const x: u32 = computeOrDie() catch fatal("compute failed");`)}

noreturn is special in that an expression of type noreturn can sit anywhere a value is expected — the compiler knows the surrounding code never reaches the point where the value would be used.

${z(`const value: i32 = if (cond) 42 else return; // ^^^^^^ // 'return' has type noreturn, so the else branch is fine`)}

unreachable

Related: unreachable is an expression of type noreturn that asserts "control flow can never get here." In safe builds it panics if reached; in ReleaseFast it is undefined behavior the compiler can use to optimize.

${z(`fn dispatch(op: enum { add, sub, mul }) i32 { return switch (op) { .add => 1, .sub => 2, .mul => 3, // exhaustive switch on an enum needs no else — but if you do: // else => unreachable, }; }`)} ${danger("Don't lie", "

If you mark a path unreachable and it turns out to be reachable, your program has undefined behavior in ReleaseFast. Use it only when you've genuinely proved the path is impossible.

")}

anyerror

While we're here: anyerror is "the set of all errors." It's the most permissive error set. We'll see it properly in Part V, but mention it now so you don't see it for the first time later and panic.

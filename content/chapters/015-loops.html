Zig has exactly two loops: while for conditions, for for iterables. They look like their cousins in other languages but have a few peculiarly Zig features — capturing on null, continue expressions, and the fact that both are expressions.

while

${z(`var i: u32 = 0; while (i < 10) { std.debug.print("{}\\n", .{i}); i += 1; }`)}

continue expression

An optional "continue expression" runs after each iteration, before the condition is re-checked:

${z(`var i: u32 = 0; while (i < 10) : (i += 1) { std.debug.print("{}\\n", .{i}); }`)}

This is the closest thing Zig has to a classic C-style for(init; cond; inc). The continue expression also runs when you say continue inside the loop.

while as expression

A while with a break value yields that value. The else branch runs if the loop exits without a break:

${z(`fn firstOver(items: []const i32, threshold: i32) ?i32 { var i: usize = 0; return while (i < items.len) : (i += 1) { if (items[i] > threshold) break items[i]; } else null; }`)}

while on optionals

The capturing form unwraps an optional each iteration; the loop ends when it sees null:

${z(`var iter = collection.iterator(); while (iter.next()) |item| { process(item); }`)}

while on error unions

${z(`while (queue.pop()) |item| { process(item); } else |err| { std.debug.print("queue error: {}\\n", .{err}); }`)}

for

for iterates over arrays, slices, and integer ranges. There is no general iterator protocol like Rust's Iterator or Python's iterables; for custom iteration you write a next method and use while (as above).

${z(`const items = [_]i32{ 10, 20, 30 }; for (items) |x| { _ = x; } // by value for (items, 0..) |x, i| { _ = x; _ = i; } // with index for (&items) |*p| { _ = p; } // by pointer // Multiple inputs in lockstep: const keys = [_][]const u8{ "a", "b" }; const vals = [_]u32{ 1, 2 }; for (keys, vals) |k, v| { _ = k; _ = v; } // Integer range — half open: for (0..10) |i| { std.debug.print("{}\\n", .{i}); } // Range with a non-zero start: for (5..15) |i| { _ = i; } // Iterate by pointer when you want to mutate: var buf = [_]u8{ 1, 2, 3 }; for (&buf) |*b| b.* += 1; // buf is now { 2, 3, 4 }`)}

for as expression, break with a value

${z(`const matched: ?usize = for (haystack, 0..) |c, i| { if (c == needle) break i; } else null;`)}

continue and labeled loops

You can label a loop and break or continue out of a nested one:

${z(`outer: for (rows) |row| { for (row) |cell| { if (cell == 0) continue :outer; process(cell); } }`)}

inline loops

Prefix for or while with inline to unroll the loop at compile time, which is useful when iterating over a tuple of mixed types:

${z(`const Pair = struct { name: []const u8, value: anytype }; inline for (.{ "a", "b", "c" }, .{ 1, 2.5, true }) |name, val| { std.debug.print("{s} = {}\\n", .{ name, val }); }`)}

inline only makes sense when the iteration count and the element types are compile-time known.

Loops are not statements

Loops without a break value still type as void (or ?T/!T depending on the form). The general rule: if you can take a value out, the loop's type reflects that.

${z(`// loop that always returns from inside is noreturn: const n: u32 = while (true) { if (try doThing()) |x| break x; };`)}

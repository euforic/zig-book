Zig has only two conditional constructs: if and switch. Both are expressions: they yield a value. Both are exhaustive in the sense the compiler can verify. They handle ordinary booleans, optionals, and error unions in slightly different shapes — but the shapes are consistent and limited.

if as a statement

${z(`const x: i32 = 42; if (x > 0) { std.debug.print("positive\\n", .{}); } else if (x < 0) { std.debug.print("negative\\n", .{}); } else { std.debug.print("zero\\n", .{}); }`)}

The condition must be a bool — no implicit conversion from integers, pointers, or anything else.

if as an expression

${z(`const x: i32 = -5; const sign: i8 = if (x > 0) 1 else if (x < 0) -1 else 0;`)}

The result type is the common type of the branches. If one branch is noreturn (like return or unreachable) it doesn't participate in the type, which is how single-line guards work cleanly:

${z(`const value: i32 = if (input < 0) return error.Negative else input;`)}

if with optionals

Zig's if doubles as the unwrap form for optional types. The syntax if (opt) |val| { ... } runs the block with val bound when opt is non-null:

${z(`var maybe: ?u32 = 42; if (maybe) |v| { std.debug.print("got {}\\n", .{v}); } else { std.debug.print("nothing\\n", .{}); } // Capture by pointer if you need to mutate: if (maybe) |*v| { v.* = 100; }`)}

This replaces the C idiom of "test for non-null, then dereference." The compiler verifies the variable is non-null inside the block.

if with error unions

The same shape works for error unions. The captured value is the success type; the else clause can capture the error:

${z(`const result: anyerror!u32 = parseInt(input); if (result) |n| { std.debug.print("parsed {}\\n", .{n}); } else |err| { std.debug.print("failed: {s}\\n", .{@errorName(err)}); }`)}

This is one way to handle errors locally. The other ways — try and catch — we cover in Part V.

switch

Zig's switch is exhaustive, optionally returns a value, and works on any type with a finite set of values: integers, enums, error sets, tagged unions, and small ranges.

${z(`const day: u8 = 3; const name = switch (day) { 0 => "Sunday", 1 => "Monday", 2 => "Tuesday", 3 => "Wednesday", 4 => "Thursday", 5 => "Friday", 6 => "Saturday", else => "?", };`)}

Patterns can be single values, ranges, lists, or else:

${z(`const x: i32 = 42; const category = switch (x) { 0 => "zero", 1, 2, 3 => "small", 4...10 => "medium", 11...100 => "large", else => "huge", };`)}

Ranges use a...b (inclusive at both ends). Lists use commas. else catches everything not covered.

switch on enums

Switching on an enum and covering every case lets you drop the else:

${z(`const Color = enum { red, green, blue }; fn rgb(c: Color) [3]u8 { return switch (c) { .red => .{ 255, 0, 0 }, .green => .{ 0, 255, 0 }, .blue => .{ 0, 0, 255 }, }; }`)}

If you add a fourth color later, the compiler will flag every switch that became non-exhaustive. This is one of Zig's most useful safety features.

Capturing in switch

When switching on a tagged union or an optional, you can capture the payload:

${z(`const Token = union(enum) { int: i64, str: []const u8, sym: u8, }; fn describe(t: Token) void { switch (t) { .int => |n| std.debug.print("int {}\\n", .{n}), .str => |s| std.debug.print("str \\"{s}\\"\\n", .{s}), .sym => |c| std.debug.print("sym {c}\\n", .{c}), } }`)}

Capture by pointer with |*payload| if you want to mutate the union in place.

Labeled switch and continue

A relatively new (post-0.12) feature: switch can carry a label and have its branches re-dispatch with continue :label. This is a clean way to write state machines without an outer loop.

${z(`const State = enum { idle, running, done }; fn run(initial: State) void { sw: switch (initial) { .idle => { std.debug.print("starting\\n", .{}); continue :sw .running; }, .running => { std.debug.print("running\\n", .{}); continue :sw .done; }, .done => { std.debug.print("finished\\n", .{}); // fall through; switch exits }, } }`)}

The dispatch table is reused, and the compiler can generate a tight indirect-jump sequence. We'll return to this pattern in Chapter 37.

Inline switch

Prefix a switch prong with inline to unroll it at compile time when the discriminator is comptime-known:

${z(`fn sizeOf(comptime T: type) usize { return switch (T) { u8 => 1, u16, i16 => 2, u32, i32, f32 => 4, u64, i64, f64 => 8, else => @sizeOf(T), }; }`)}

Use inline else to peel out an inline catchall.

Compile-time conditional values

Because everything is an expression, the typical "ternary" use case is just if:

${z(`const verbose = false; const log_level = if (verbose) 3 else 1;`)}

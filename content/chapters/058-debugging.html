When something goes wrong, Zig gives you a lot. Safety builds catch undefined behavior at runtime with a labeled panic. The compiler embeds DWARF debug info so a real debugger can step through your code. Logs route through a configurable backend. And in 0.16, stack traces are noticeably better across every target.

Panics

A panic is the runtime equivalent of "something the language said could never happen, just happened." Common triggers: integer overflow in a Debug build, OOB array access, unreachable code reached, slicing with bad bounds, hitting an explicit @panic.

${code('text', `thread 1234 panic: integer overflow /home/me/project/src/main.zig:42:18: 0x10043ab in tally (main) total += value; ^ /home/me/project/src/main.zig:30:13: 0x100456c in main (main) tally(items); ^`)}

The trace shows file, line, column, mangled function name, and the offending source line. On supported targets, parent frames are included so you can follow the call path to the failing operation.

Error return traces

Errors thread through try propagation. When an error reaches a boundary that prints it, the runtime can show the chain of returns that produced it — useful when a deep helper failed and you want to see the path:

${code('text', `error: PermissionDenied /home/me/project/src/fs.zig:88:9: 0x10059aa in readFile return error.PermissionDenied; ^ /home/me/project/src/config.zig:42:14: 0x1004e21 in loadConfig const data = try readFile(path); ^ /home/me/project/src/main.zig:12:5: 0x10046cd in main try loadConfig("settings.toml"); ^`)} ${note('Error return traces are enabled by default in Debug and ReleaseSafe. In ReleaseFast/ReleaseSmall they\\u2019re elided for performance. If you want them in fast builds, use std.builtin.optimize_mode conditionally or build with -fno-strip.')}

Using a debugger

Zig binaries include DWARF debug info by default in Debug builds. GDB and LLDB work out of the box:

${sh(`# Compile with maximum debug info zig build -Doptimize=Debug # Launch under lldb lldb zig-out/bin/myapp # In lldb: # b src/main.zig:42 # breakpoint by file/line # r # run # n # next line # s # step into # p variable_name # print a value # bt # backtrace`)}

For GDB the commands are similar (break, run, next, step, print, backtrace). VS Code with the CodeLLDB extension gives you graphical stepping.

Inspecting Zig types in a debugger

Tagged unions, slices, and optionals have natural representations:

  • A slice prints as { ptr = 0x..., len = N }. Use p mySlice.ptr[0] to inspect contents.
  • An optional is { payload = ..., is_some = 1 } or similar; check the discriminant first.
  • A tagged union shows the active variant. p u.case_name.field pulls out the data.

std.log

Routing diagnostic output through a real logger is more maintainable than ad-hoc print calls:

${z(`const std = @import("std"); const log = std.log.scoped(.parser); pub fn parse(input: []const u8) !void { log.debug("parsing {d} bytes", .{input.len}); if (input.len == 0) { log.warn("empty input", .{}); return error.Empty; } // ... }`)}

Scopes (std.log.scoped(.name)) tag messages so you can filter by subsystem. Levels (err, warn, info, debug) control verbosity. The default backend writes to stderr; override std.log.defaultLog for custom destinations (a file, a ring buffer, a remote sink).

std.debug.print

For quick "just print it" debugging, std.debug.print(fmt, args) writes formatted text to stderr unconditionally. It bypasses logger configuration, so it always shows up. Use it for one-shot investigation, then promote to std.log for keeps.

Sanitizers and safety modes

Zig's safety checks are sanitizers, baked into the language. Debug and ReleaseSafe builds include checks for:

  • Integer overflow (use +%, -%, *% for wrapping arithmetic when you want it).
  • Bounds violations on arrays and slices.
  • Misaligned pointer casts.
  • Reaching unreachable.
  • Invalid enum tags.

You don't need ASan or UBSan — for the most common classes of memory and arithmetic bugs, Zig's own checks are equivalent and bundled in.

${tip('If a panic message points at a line but the cause is upstream, look at the values in the trace. Many panics ("integer overflow", "index out of bounds") name the operation but not the inputs. std.debug.print the relevant variables one frame up, or break in a debugger.')}

strace and dtrace

For system-level debugging — "why is this syscall failing?" — Zig binaries are normal native binaries. strace on Linux, dtruss on macOS, and Process Monitor on Windows all work without modification.

${warn('In ReleaseFast and ReleaseSmall, integer overflow is undefined behavior. The compiler may assume it does not happen and optimize accordingly. If your code depends on wrapping semantics, use the +% family of operators explicitly so the behavior is portable across optimization modes.')}

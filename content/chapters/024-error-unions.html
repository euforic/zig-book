The type !T is shorthand for "the inferred error set, or a value of type T." Spelled long, it's ErrorSet!Payload. Under the hood, an error union is a tagged union: either an error code, or a payload.

Constructing an error union

Return either an error or a value from a function with an !T return:

${z(`fn half(x: i32) !i32 { if (@mod(x, 2) != 0) return error.NotEven; return @divExact(x, 2); }`)}

You don't wrap the success value in anything — it's a plain return. The error path uses return error.X.

Catching with catch

The catch expression unwraps an error union. If success, the expression evaluates to the payload. If error, the right-hand side runs:

${z(`const n = half(7) catch 0; // default value on error const m = half(7) catch return; // propagate (rarely; use try) const k = half(7) catch |e| blk: { std.log.warn("half failed: {}", .{e}); break :blk -1; };`)}

The |e| capture names the error value so you can inspect it. Without a capture, the error is discarded.

try is sugar for catch-and-return

Almost every error you encounter, you want to bubble up. try expr is exactly expr catch |e| return e:

${z(`fn doubleHalf(x: i32) !i32 { const h = try half(x); // bubble up error.NotEven return h * 2; }`)}

If half returns an error, doubleHalf returns the same error. If success, h binds to the payload and execution continues.

${tip("Almost always use try", "

If you're not handling the error here — turning it into a different error, defaulting to a value, logging it — use try. Reserve catch for the leaf nodes of your error flow.

")}

Error union returns and inference

When the return type is !T, Zig infers the error set by union-ing every error a try or return error.X could produce:

${z(`const std = @import("std"); fn loadConfig(io: std.Io, allocator: std.mem.Allocator, path: []const u8) ![]u8 { return try std.Io.Dir.cwd().readFileAlloc(io, path, allocator, .limited(1 << 20)); }`)}

The inferred set includes every error readFileAlloc can return. You don't have to write it.

Coercion into wider sets

A narrow error union coerces into a wider one automatically:

${z(`fn small() error{A}!u8 { return error.A; } fn big() error{A, B}!u8 { return try small(); // ok: {A} is subset of {A,B} }`)}

Going the other way — wide to narrow — is a compile error unless you switch on the error and reconstruct.

Payload size

An error union takes max(sizeOfError, sizeOfPayload) plus a discriminator, minus niche optimizations. Errors are typically small (16 bits or so), so !T rarely costs more than T itself.

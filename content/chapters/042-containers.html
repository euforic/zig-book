Zig's standard containers live mostly in std.array_list, std.hash_map, std.array_hash_map, and the linked-list modules. The important 0.16 lesson is that container ownership is explicit: some containers store an allocator, some make you pass one to mutation methods, and you should know which kind you are holding.

std.ArrayList(T), std.array_hash_map.Auto, std.PriorityQueue, and std.PriorityDequeue use .empty plus allocator-at-call-site methods. std.AutoHashMap and std.StringHashMap store an allocator; use their Unmanaged variants when you want allocator-at-call-site behavior.

ArrayList: the dynamic array

${z(`const std = @import("std"); pub fn main() !void { var gpa: std.heap.GeneralPurposeAllocator(.{}) = .init; defer _ = gpa.deinit(); const allocator = gpa.allocator(); var list: std.ArrayList(u32) = .empty; defer list.deinit(allocator); try list.append(allocator, 1); try list.append(allocator, 2); try list.append(allocator, 3); for (list.items) |x| std.debug.print("{}\\n", .{x}); }`)}

Notice the allocator at every mutation. list.items is a plain []T slice — pass it to any function that takes a slice. list.capacity is the backing capacity.

Common ArrayList operations

${z(`try list.append(allocator, x); try list.appendSlice(allocator, &[_]u32{4,5,6}); try list.insert(allocator, idx, x); const popped = list.pop(); // ?T const last = list.getLast(); // T (asserts not empty) list.clearRetainingCapacity(); // length=0, capacity kept list.clearAndFree(allocator); // free buffer try list.ensureTotalCapacity(allocator, 1024); // reserve list.appendAssumeCapacity(x); // skip the check try list.resize(allocator, 100); // grow or shrink`)}

The AssumeCapacity variants are the way to write hot loops: ensure once, append-without-realloc-check thousands of times.

Stack-backed ArrayList

For a fixed-capacity dynamic list, initialize an ArrayList from a caller-provided buffer:

${z(`var storage: [16]u32 = undefined; var small: std.ArrayList(u32) = .initBuffer(&storage); try small.appendBounded(10); try small.appendBounded(20); // No allocator, no heap; appending past capacity returns error.OutOfMemory. for (small.items) |x| std.debug.print("{}\\n", .{x});`)}

HashMap: keys to values

${z(`var map = std.AutoHashMap(u32, []const u8).init(allocator); defer map.deinit(); try map.put(1, "one"); try map.put(2, "two"); if (map.get(1)) |v| std.debug.print("{s}\\n", .{v}); if (map.contains(2)) {} var it = map.iterator(); while (it.next()) |entry| { std.debug.print("{} -> {s}\\n", .{entry.key_ptr.*, entry.value_ptr.*}); }`)}

AutoHashMap picks the hash and equality from the key type automatically and stores the allocator internally. There's also HashMap (you supply your own hash context), StringHashMap (a specialization for []const u8 keys), and *Unmanaged variants that take an allocator on mutating calls.

Hash map flavors

  • AutoHashMap(K, V) — key type auto-hashed; stores its allocator.
  • AutoHashMapUnmanaged(K, V) — same hashing, allocator passed to mutation methods.
  • StringHashMap(V) — keys are []const u8; useful for parsed config, JSON, etc.
  • HashMap(K, V, Context, max_load_pct) — supply your own context with hash and eql methods.
  • std.array_hash_map.Auto(K, V) — order-preserving, allocator-at-call-site map.

String maps and string-as-key

${z(`var counts = std.StringHashMap(u32).init(allocator); defer counts.deinit(); for (words) |w| { const gop = try counts.getOrPut(w); if (gop.found_existing) { gop.value_ptr.* += 1; } else { gop.value_ptr.* = 1; } }`)}

getOrPut is the idiomatic "increment-or-insert" primitive. It returns pointers to the slot, so you can branch on whether it existed without two lookups.

${warn("StringHashMap doesn't copy keys", "

When you put a string key, the map stores the slice pointer — not a copy. If the underlying memory goes away, the key is dangling. To own the key, duplicate it first with try allocator.dupe(u8, key), insert the duplicate, and free owned keys when you remove entries or deinitialize the map.

")}

Order-preserving maps

Use std.array_hash_map.Auto, std.array_hash_map.String, or std.array_hash_map.Custom when iteration order matters:

${z(`var ordered: std.array_hash_map.Auto(u32, []const u8) = .empty; defer ordered.deinit(allocator); try ordered.put(allocator, 10, "ten"); try ordered.put(allocator, 20, "twenty"); for (ordered.keys(), ordered.values()) |key, value| { std.debug.print("{} -> {s}\\n", .{ key, value }); }`)}

Other containers

The stdlib also includes:

  • std.MultiArrayList(S) — "struct of arrays" layout for cache-friendly hot loops over fields.
  • std.SinglyLinkedList / std.DoublyLinkedList — non-generic intrusive linked lists; put a Node field inside your payload.
  • std.PriorityQueue(T, Context, lessThan) — binary heap; initialized with .empty in 0.16.
  • std.Deque(T) — double-ended queue.
  • std.SegmentedList(T, chunk_size) — list that never invalidates pointers on growth.

Iteration patterns

${z(`// Index plus value (built-in trick) for (list.items, 0..) |x, i| { std.debug.print("[{}] = {}\\n", .{i, x}); } // Remove while iterating: collect indices, then remove var to_remove: std.ArrayList(usize) = .empty; defer to_remove.deinit(allocator); for (list.items, 0..) |x, i| if (x == 0) try to_remove.append(allocator, i); var j = to_remove.items.len; while (j > 0) { j -= 1; _ = list.orderedRemove(to_remove.items[j]); }`)}

Removing while iterating is a perennial Zig gotcha — the slice from .items doesn't update if you mutate. Collect indices first.

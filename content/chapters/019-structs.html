The struct is Zig's main composite type. It is what you use for records, modules, classes (such as they are), and namespaces. The same keyword does all those jobs because they're really the same thing.

Basic struct

${z(`const Point = struct { x: f32, y: f32, }; const p: Point = .{ .x = 3.0, .y = 4.0 }; const q = Point{ .x = 1.0, .y = 2.0 }; std.debug.print("{} {}\\n", .{ p.x, p.y });`)}

You access fields with . and initialize with .{ ... }. The shorthand .{ ... } without a type before it is an anonymous struct literal that takes the type from context.

Default field values

${z(`const Config = struct { timeout_ms: u32 = 5000, retries: u8 = 3, name: []const u8 = "default", }; const c: Config = .{}; // all defaults const d: Config = .{ .timeout_ms = 10_000 }; // override one`)}

Methods

Methods are just functions inside the struct declaration. The first parameter is conventionally self:

${z(`const Point = struct { x: f32, y: f32, pub fn add(self: Point, other: Point) Point { return .{ .x = self.x + other.x, .y = self.y + other.y }; } pub fn scale(self: *Point, factor: f32) void { self.x *= factor; self.y *= factor; } pub fn length(self: Point) f32 { return @sqrt(self.x * self.x + self.y * self.y); } }; var p: Point = .{ .x = 3, .y = 4 }; const len = p.length(); // 5.0 const sum = p.add(.{ .x = 1, .y = 1 }); p.scale(2.0);`)}

By value (self: Point) for read-only methods; by pointer (self: *Point) for mutating methods. Method-call syntax p.method() is sugar for Point.method(p, ...) with automatic & if the method takes a pointer.

Static methods and namespaces

A function inside a struct that doesn't take self is a "static" function — but really it's just a function in the struct's namespace:

${z(`const Point = struct { x: f32, y: f32, pub const origin: Point = .{ .x = 0, .y = 0 }; pub fn init(x: f32, y: f32) Point { return .{ .x = x, .y = y }; } }; const o = Point.origin; const p = Point.init(3, 4);`)}

Constants, types, and functions can all sit inside a struct declaration. This is how you build Zig "modules": a file is itself a struct, and its top-level declarations are its members.

Files are structs

The most important thing in this chapter. When you write const std = @import("std");, the result is a type — specifically, the struct type of std's root file. Members of the file are members of the struct.

${z(`// math.zig pub const PI: f64 = 3.141592653589793; pub const Circle = struct { radius: f64, pub fn area(self: Circle) f64 { return PI * self.radius * self.radius; } }; pub fn double(x: f64) f64 { return x * 2; }`)} ${z(`// main.zig const math = @import("math.zig"); const c: math.Circle = .{ .radius = 5 }; const a = c.area(); const pi = math.PI;`)}

This is the entire module system. There is no module keyword, no manifest of exports, no export default. A file is a struct; pub declarations are its public members.

Anonymous structs

You can use .{ ... } wherever a struct value is expected. If there's no type to infer from, the literal has an anonymous type:

${z(`fn printPair(p: anytype) void { std.debug.print("{} {}\\n", .{ p.x, p.y }); } printPair(.{ .x = 3, .y = 4 }); printPair(.{ .x = "hello", .y = "world" });`)}

Tuples

An anonymous struct literal with only positional fields is a tuple:

${z(`const t = .{ 1, "two", 3.0 }; const a = t[0]; const b = t[1]; const c = t.@"2"; // also works`)}

Tuples are mainly useful as the argument list for variadic-like functions (which is exactly how std.debug.print uses them) and for ad-hoc grouping.

Memory layout and packed

By default Zig is free to reorder fields and choose padding. If you need a specific layout (for hardware registers, network protocols, FFI), use extern struct for C-compatible layout or packed struct for bit-level packing:

${z(`const Header = extern struct { magic: u32, version: u16, flags: u16, }; const Bits = packed struct(u32) { op: u4, reg: u4, addr: u24, }; const b: Bits = .{ .op = 1, .reg = 2, .addr = 0x123456 }; const as_int: u32 = @bitCast(b);`)}

packed struct(T) requires fields to total exactly the width of the backing integer T. We'll cover both in detail in Chapter 33.

@This()

Inside a struct declaration, @This() returns the type itself. This is how generic structs refer to their own type without naming it:

${z(`fn LinkedList(comptime T: type) type { return struct { const Self = @This(); head: ?*Node = null, const Node = struct { value: T, next: ?*Node = null, }; pub fn push(self: *Self, n: *Node) void { n.next = self.head; self.head = n; } }; }`)}

@This() is the only way to get the enclosing struct's type when the struct is anonymous (as inside fn LinkedList(...) type { return struct { ... }; }).

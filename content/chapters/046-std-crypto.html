std.crypto is one of the standard library's gems. Zig ships a curated set of modern cryptographic primitives — hashes, MACs, AEADs, signature schemes, key-agreement, KDFs — all implemented in pure Zig, all constant-time, all suitable for production. No need to pull in OpenSSL or libsodium for the common cases.

Hashing

${z(`const std = @import("std"); pub fn main() void { var sha = std.crypto.hash.sha2.Sha256.init(.{}); sha.update("hello, "); sha.update("world"); var digest: [32]u8 = undefined; sha.final(&digest); std.debug.print("{x}\\n", .{std.fmt.fmtSliceHexLower(&digest)}); }`)}

The hash API is consistent: init, update any number of times, final into a buffer. Available algorithms: SHA-1, SHA-2 (224/256/384/512), SHA-3 (224/256/384/512), Blake2b, Blake2s, Blake3.

One-shot hashes

${z(`var out: [32]u8 = undefined; std.crypto.hash.sha2.Sha256.hash("the message", &out, .{});`)}

For when you have the whole input in memory and don't need streaming.

MACs

${z(`var mac: [32]u8 = undefined; std.crypto.auth.hmac.sha2.HmacSha256.create(&mac, "data", "secret key"); const verified = std.mem.eql(u8, &mac, &expected_mac); // use timingSafeEql for security`)}

Always compare MACs and signatures with std.crypto.utils.timingSafeEql, not with std.mem.eql. The former takes constant time; the latter short-circuits and can leak the prefix.

Authenticated encryption (AEAD)

${z(`const Aes256Gcm = std.crypto.aead.aes_gcm.Aes256Gcm; var key: [Aes256Gcm.key_length]u8 = undefined; io.random(&key); var nonce: [Aes256Gcm.nonce_length]u8 = undefined; io.random(&nonce); const plaintext = "secret message"; var ciphertext: [plaintext.len]u8 = undefined; var tag: [Aes256Gcm.tag_length]u8 = undefined; Aes256Gcm.encrypt(&ciphertext, &tag, plaintext, "associated data", nonce, key); var recovered: [plaintext.len]u8 = undefined; try Aes256Gcm.decrypt(&recovered, &ciphertext, tag, "associated data", nonce, key);`)}

The AEAD shape is the same for every cipher: encrypt and decrypt take separate buffers for plaintext, ciphertext, and tag, plus AAD, nonce, and key.

Available AEADs

  • aes_gcm — AES-128/256-GCM. Industry standard.
  • aes_siv — AES-SIV. Nonce-misuse-resistant.
  • aes_gcm_siv — AES-GCM-SIV. The SIV variant of GCM.
  • chacha_poly — ChaCha20-Poly1305 and XChaCha20-Poly1305. Software-friendly.
  • ascon — Ascon-AEAD. Lightweight for embedded.

Key derivation

${z(`var key: [32]u8 = undefined; try std.crypto.pwhash.argon2.kdf(allocator, &key, "password", "salt12345678", .{ .t = 3, .m = 65536, .p = 1, }, .argon2id);`)}

For password hashing, Argon2 is the default. scrypt and pbkdf2 are also available for compatibility.

Signatures and key exchange

${z(`// Ed25519 const kp = std.crypto.sign.Ed25519.KeyPair.create(null) catch unreachable; const sig = try kp.sign("message", null); try sig.verify("message", kp.public_key); // X25519 const a_kp = std.crypto.dh.X25519.KeyPair.create(null) catch unreachable; const b_kp = std.crypto.dh.X25519.KeyPair.create(null) catch unreachable; const shared_a = try std.crypto.dh.X25519.scalarmult(a_kp.secret_key, b_kp.public_key); const shared_b = try std.crypto.dh.X25519.scalarmult(b_kp.secret_key, a_kp.public_key); // shared_a == shared_b`)}

Ed25519, ECDSA over secp256r1/k1, and X25519 cover the public-key needs for most applications. Post-quantum primitives (ML-KEM, ML-DSA) are being added as their standards stabilize.

Random

${z(`var buf: [32]u8 = undefined; io.random(&buf); try io.randomSecure(&buf); const io_source: std.Random.IoSource = .{ .io = io }; const crypto_rng = io_source.interface(); const r = crypto_rng.int(u64); var prng = std.Random.DefaultPrng.init(0x1234_5678); const deterministic_rng = prng.random(); const f = deterministic_rng.float(f64);`)}

io.random fills bytes from the selected I/O implementation and may use process-local RNG state. io.randomSecure asks outside the process for fresh cryptographic entropy. For deterministic simulations, tests, and games, use std.Random PRNGs with an explicit seed.

${danger("Don't roll your own", "

If you find yourself reaching for raw block ciphers, manual padding, or ad-hoc protocols, stop and use a higher-level primitive. AES-GCM-SIV, ChaCha20-Poly1305, and Ed25519 are correct by construction; AES-ECB and \"encrypt then HMAC by hand\" are not. The stdlib makes the right thing the easy thing — use it.

TLS

std.crypto.tls contains a TLS 1.3 implementation used by std.http.Client. It is not yet a general-purpose TLS library suitable for arbitrary clients and servers — that's a known roadmap item. For now, if you need TLS outside HTTP, use a bound library.
